01 Chat — Blocked State in Thread

Users see a blocked UI inside the chat thread instead of being kicked out after blocking.

User Flow

  • Open chat thread with a friend → tap header menu → Block
  • User stays on the thread; composer is replaced with blocked notice + unblock bar
  • Unblock from header menu or bottom bar restores messaging
  • Sending is guarded while blocked (ChatThreadCubit checks relationship)

Implementation

LayerFiles / APIs
UIchat_thread_blocked.dart, chat_thread_page.dart, chat_thread_menu.dart
Statechat_thread_cubit.dart — blockUser(), unblockUser(), isBlocked
DomainFriendsRepository.blockUser() / unblockUser()
Backenduser_blocks table (friends schema migration)
DIinjection.dart — FriendsRepository injected into ChatThreadCubit

Data Flow

User taps Block → MomentDialog.confirm() → FriendsRepository.blockUser(userId) → INSERT user_blocks + remove friendship → ChatThreadCubit.refreshRelationship() → UI: ChatThreadBlockedNotice + ChatThreadBlockedBar → sendMessage() / onComposerChanged() no-op while blocked

Pin, mute, delete, block — full stack from UI to Supabase.

User Flow

  • Chat tab → long-press any conversation
  • Bottom sheet: View profile, Pin/Unpin, Mute/Unmute, Delete chat, Block/Unblock
  • Pinned chats sort to top; muted shows bell-off icon; pinned shows pin icon
  • Optimistic UI updates via ChatInboxCubit

Backend — chat_conversation_settings

Long-press → Pin chat → ChatInboxCubit.pinConversation(id) [optimistic UI] → ChatRepository.setConversationPinned(pinned: true) → UPSERT chat_conversation_settings (is_pinned, pinned_at) → Realtime triggers inbox refresh → Conversation sorted to top

08 Chat — Delete Conversation (Full Clear)

Delete chat removes all messages from the database, not just hiding the inbox row.

User Flow

  • Long-press chat → Delete chat → confirm
  • Conversation removed from inbox; all messages deleted server-side
  • Re-open friend → empty thread; new messages start fresh
  • Note: Deletes entire message history for both participants

Backend RPC — delete_chat_conversation(p_conversation_id)

Migration: 20260829170000_delete_chat_conversation.sql

  1. Validate caller is conversation participant
  2. DELETE chat_typing rows
  3. DELETE all chat_messages (reactions, stars, hidden cascade)
  4. RESET last_message_preview + last_message_at on conversation
  5. UPSERT settings: is_hidden = true, unpin

Fresh Chat Restart

getOrCreateConversation(otherUserId) → RPC get_or_create_chat_conversation → _unhideConversation() sets is_hidden = false → Thread loads with zero messages → New message INSERT triggers chat_touch_conversation trigger

09 Chat Thread — Loading UX (No Flicker)

Shimmer while loading; stable transition to messages or empty state.

Problem Fixed

  • Old behavior: messages → loading → empty → messages (flicker)
  • Cause: realtime stream emitted [] before initial fetch completed

Solution

ChangeLocation
hasCompletedInitialLoad flag on statechat_thread_cubit.dart
_acceptStreamUpdates — ignore stream until initial load donechat_thread_cubit.dart
Don't emit empty from watchMessages when lastRows.isEmptychat_remote_data_source.dart
UI: shimmer until hasCompletedInitialLoadchat_thread_page.dart
Error state with retry when load failschat_thread_page.dart

UI States

Open thread → ChatThreadShimmer (hasCompletedInitialLoad = false) → getOrCreateConversation + getMessages → ready + messages OR empty timeline OR blocked notice OR error state → stream updates only after initial load
